Part 1 · First principles

It's all just switches

A computer can't store a "7" or a letter "A" or a photo. Deep down it only has millions of tiny switches, each either on (1) or off (0). Everything else — numbers, text, music, this webpage — is just clever patterns of those switches. One switch is a bit. Eight of them make a byte.

These 8 switches make the number 0  (binary 00000000)

Try to make 13. Then the biggest number you can — why does it stop there? Eight switches can only count from 0 to 255. That's why a byte has 256 possible values.

Numbers

Count with powers of two instead of tens. 1101 = 8+4+0+1 = 13. That's the whole trick.

Text

Every letter is secretly a number. Capital A is 65, B is 66… This rule is called ASCII (full table ↗).

Try it

Type a number 0–255, see its binary:

65 is binary 01000001 — and the letter A. Same bits, different meaning. Context is everything.

0&1

The big idea: a computer never "understands" anything. It just moves patterns of on/off around, insanely fast, following rules we give it. The rest of today is about what those rules look like.

Part 3 · Inside the box

The CPU: fast, and gloriously stupid

A processor (CPU) does one boring thing, billions of times a second. It's called the fetch–execute cycle:

1 · Fetch

Grab the next instruction from memory. The program counter (PC) remembers which one is next.

2 · Decode

Work out what it says — "add these", "load that", "jump there".

3 · Execute

Do it. Usually shuffle a number between a register and memory, or do one sum.

4 · Repeat

Move the PC to the next instruction and start again. Forever.

The two places a CPU keeps numbers

Registers — the desk

pcwhich instruction is next
a0a number being worked on
a1another number
t0scratch / temporary
sptop of the stack

A tiny handful of slots (about 32) right inside the CPU. Lightning fast, but there's almost no room. Like the top of your desk — only what you're using right now.

Memory — the filing cabinet

.textthe program's instructions
.datavalues the program set up
stackworking notes, grows & shrinks
0x10000the 64×64 screen (later!)

Millions of numbered slots (addresses). Much bigger, a little slower. The CPU is forever carrying numbers between the cabinet and the desk.

Watch for this in the Workbench: the Registers panel is the desk, the Memory panel is the cabinet, and the PC is the finger pointing at the next instruction. Everything you do today is one of these two places changing.

1

Make it add 2 + 2

~20 min

Goal: watch a single instruction run and change a number before your eyes.

  1. Open the Workbench. In the top-left C code box, find the line that prints something and change it so the whole program is just this:
int main() {
    print_int(2 + 2);   // ask the CPU to add, then show the answer
    return 0;
}
  1. Look at the Assembly panel. Your one line of C just turned into several lines of assembly — the CPU's real language. Don't worry about every line; find one that looks like addi or add. That's the actual addition.
  2. Now slow it right down. Set the speed to 8 instructions/second (or use the Step button to go one at a time).
  3. Press Step and keep your eyes on the Registers panel. Watch the pc value tick forward each press — that's the CPU walking down the instructions.
  4. Keep stepping until a 4 appears in a register (often a0), then lands in the Console. You just watched arithmetic happen at the level the machine really works.
Predict first: before you press Step, how many times do you think you'll press it before the answer shows up? Write your guess, then count.
🏋️ Stretch: Change 2 + 2 to 7 * 6. Multiplication needs the M extension — check the ISA selector says RV32IM or RV32IMA. Can you spot the mul instruction appear in the assembly?
2

Poke the machine by hand

~15 min

Goal: prove the registers and memory are just numbers you can reach in and change.

  1. With any small program loaded, Reset, then Step a few times so some registers hold values.
  2. In the Registers panel, click a value (try t0 or a1) and type a new number — say 99. The CPU now believes that. Nothing checked. Nothing asked permission.
  3. Do the same in the Memory panel: click a slot in the .data area and change it. You've just edited the machine's "filing cabinet" directly.
  4. Press Run and see how your change ripples through the rest of the program.
Research: if changing a number is this easy, how does a real computer stop a game (or a virus) from scribbling over something important? Hold that thought — that's the whole field of cyber security.
🏋️ Stretch: Click into the Assembly panel and add one line of your own, e.g. addi a0, a0, 10 (it re-assembles as you type). Reset, run, and see whether the answer shifts by 10. You just hand-wrote machine code.
3

Watch C become machine code

~15 min

Goal: see how one friendly line of a programming language explodes into many tiny CPU steps.

  1. Replace the program with this loop, which adds up the numbers 1 to 10:
int main() {
    int total = 0;
    for (int i = 1; i <= 10; i++) {
        total = total + i;     // add the next number
    }
    print_int(total);          // should be 55
    return 0;
}
  1. Before running: work out on paper what total should be. (1+2+3…+10.)
  2. Run it. Did you get 55?
  3. Now look at the Assembly panel and count the lines. Three lines of C became many instructions — because the CPU has no idea what a "loop" is. It only knows "add" and "jump back if not finished yet".
  4. Can you identify the instruction in the Assembly panel that makes the loop start again?
Big realisation: a "loop" is an illusion built from jumping backwards. Every loop you'll ever write, in any language, becomes this underneath.
🏋️ Stretch: Change i <= 10 to i <= 100. New answer? Then try making it count only the even numbers (hint: i = i + 2 and start at 2).
4

Paint pixels straight into memory

~15 min

Goal: the payoff — draw on a real screen by writing numbers into memory, exactly how every screen you own works.

The Workbench has a 64×64 screen that lives in memory starting at address 0x10000. Each pixel is one byte — one number 0–255 — that sets its colour (3 bits red, 3 green, 2 blue). Writing to that memory is drawing.

int main() {
    // treat memory from 0x10000 as a row of pixels
    char* screen = (char*)0x10000;
    for (int i = 0; i < 64*64; i++) {
        screen[i] = 0xE0;      // 0xE0 = full red
    }
    return 0;
}
  1. Run it. The whole screen should turn red. You didn't call a "draw" function — you just wrote numbers into slots, and the screen shows whatever's there.
  2. Try other colours: 0x1C = green, 0x03 = blue, 0xFF = white, 0x00 = black.
  3. Make stripes instead of a fill. Replace the line inside the loop with:
        screen[i] = (i / 8) % 2 ? 0xE0 : 0x1C;  // red / green bands
Mind-bender: the photo on your phone, this webpage, a film — all of it is just numbers being written into a block of memory like this one, many times a second. There is no "picture" anywhere. Only numbers.
🏋️ Stretch: Use the pixel's position to pick its colour and make a gradient or checkerboard. Row = i / 64, column = i % 64. What pattern can you invent? Show the person next to you.

Before you go

Why this matters for you

You don't need to have coded before today, and you don't need to decide anything now. But the fundamentals you touched today matter more than they might seem.

These fundamentals are critical

Binary, memory, and how a CPU actually runs a program aren't trivia — they're the foundation everything else in computing is built on. Skip them and higher-level ideas stop making sense.

Especially if you want to build things

Programming devices, working with hardware, writing fast or reliable software, debugging when something goes wrong — all of it comes back to understanding what's really happening underneath.

Durham's first year covers exactly this

Computer Systems is core first-year material at Durham — binary, the CPU, how programs really run — building directly on what you did today.

Cheat sheet

Words we used today

Keep this. Every one of these is a word real computer scientists use every day — and now so do you.

Bit
A single switch: 0 or 1. The smallest piece of information there is.
Byte
Eight bits together. Can hold a number from 0 to 255, or one letter.
Binary
Counting with only 0 and 1, using powers of two.
ASCII
The rule that maps letters to numbers (A = 65, B = 66…).
CPU
The processor — the part that follows instructions and does the sums.
Register
A tiny, super-fast storage slot inside the CPU. There are only a few.
Memory (RAM)
A huge set of numbered slots the CPU reads from and writes to.
Address
The "house number" of one slot in memory, e.g. 0x10000.
Program counter (PC)
The register that remembers which instruction runs next.
Instruction
One tiny thing the CPU can do: add, load, store, jump.
Assembly
Human-readable names for machine instructions (add, addi, mul…).
Machine code
The pure numbers the CPU actually runs. Assembly turns into this.
RISC-V
The open, modern instruction set our Workbench pretends to be.
Fetch–execute
The endless loop a CPU runs: get an instruction, do it, repeat.
Hexadecimal
Counting in 16s (0–9 then A–F). A tidy shorthand for binary, e.g. 0xFF = 255.
Compiler
The tool that translates C down into assembly / machine code for you.
